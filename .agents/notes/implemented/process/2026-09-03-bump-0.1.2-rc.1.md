# Agent Note: Fork baseline bump to 0.1.2-rc.1

Status: implemented

English | [中文](2026-09-03-bump-0.1.2-rc.1.zh.md)

## Problem

Upstream published `dsh-v0.1.2-rc.1` (commit `a66e47020478`). The fork still sat on `0.1.2-alpha.5` plus zw-layer patches (WKWebView `Content-Length`, MCP status events, session concurrent-writer guard, `web:log`, todo-completion guard, model-effort memory, scoped republish module ids, hierarchical compaction fallback). Leaving the fork on alpha.5 would mix official `0.1.2-rc.1` packages with a stale `@crazx` zw line once consumers retarget.

## Decision

This bump merges tag `dsh-v0.1.2-rc.1` and keeps every fork-only behavior:

- Persistence keeps upstream `SessionLogOffset`, `state.storage`, and the inherited-prefix materialize check, and still refuses appends when another process advanced the durable revision ([concurrent-writer note](../bug-fix/2026-08-18-session-append-concurrent-writer-guard.md)).
- `packages/bundle/base/cordis.patch.yml` keeps the `todo-completion-guard` row beside the upstream default that enables both `web_search` and `web_fetch` on the shared base.
- The todo-completion-guard reads the live log through `Session.snapshotEvents()` ([guard note](../feature/2026-08-19-todo-completion-guard.md)). The fork-only package version is aligned to `0.1.2-rc.1` because upstream release bumps do not touch it.
- MCP `mcp-client/status`, remembered reasoning effort, `web:log`, WKWebView `Content-Length`, scoped republish module ids, and hierarchical compaction fallback stay.

Desktop and Oh My DSH consume this fork through `runtime/revision.json` and `@crazx/*` zw publishes. Retargeting those consumers is a separate change after a maintainer merges this bump and tags `v0.1.2-rc.1+zw.1`.

## Alternatives considered

**Stay on alpha.5 and cherry-pick rc.1.** Rejected: rc.1 is a version-only release atop alpha.5; a merge preserves the full upstream release commit and avoids drift on the 252 package version fields.

**Drop the single-writer persistence guard now that official documents inherited-prefix appends.** Rejected: inherited-prefix completeness and foreign-process revision drift are different failures; official still has no cross-process writer refusal.

## Consequences

Fork consumers keep the same local patches on the `0.1.2-rc.1` line. `publish-fork --list --base 0.1.2-rc.1` remains the zw publish set; npm `@crazx/*@0.1.2-rc.1.zw.1` exists only after the post-merge tag.
