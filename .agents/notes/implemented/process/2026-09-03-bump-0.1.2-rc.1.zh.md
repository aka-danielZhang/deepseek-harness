# Agent Note: Fork 基线升到 0.1.2-rc.1

Status: implemented

[English](2026-09-03-bump-0.1.2-rc.1.md) | 中文

## Problem

上游发布了 `dsh-v0.1.2-rc.1`（提交 `a66e47020478`）。fork 仍停在 `0.1.2-alpha.5` 加 zw 层补丁（WKWebView `Content-Length`、MCP 状态事件、会话并发写守护、`web:log`、todo 完成守卫、模型推理档位记忆、scoped 重发模块 id、层次压缩 fallback）。继续停在 alpha.5 会让消费方切到官方 `0.1.2-rc.1` 后与过期的 `@crazx` zw 线混装。

## Decision

本次 bump 合入标签 `dsh-v0.1.2-rc.1`，并保留全部 fork 专有行为：

- 持久化采用上游的 `SessionLogOffset`、`state.storage` 与 inherited-prefix 物化检查，并仍在另一进程推进了 durable revision 时拒绝 append（[并发写者 note](../bug-fix/2026-08-18-session-append-concurrent-writer-guard.zh.md)）。
- `packages/bundle/base/cordis.patch.yml` 保留 `todo-completion-guard` 行，并采用上游在共享 base 上同时启用 `web_search` 与 `web_fetch` 的默认。
- todo-completion-guard 通过 `Session.snapshotEvents()` 读取实时日志（[守卫 note](../feature/2026-08-19-todo-completion-guard.zh.md)）。仅 fork 拥有的包版本对齐到 `0.1.2-rc.1`，因为上游发版 bump 碰不到它。
- MCP `mcp-client/status`、已记住的推理档位、`web:log`、WKWebView `Content-Length`、scoped 重发模块 id、层次压缩 fallback 均保留。

桌面与 Oh My DSH 仍通过 `runtime/revision.json` 与 `@crazx/*` zw 发布消费本 fork。把那些消费方钉到新基线是独立改动，前提是维护者已合入本次 bump 并打上 `v0.1.2-rc.1+zw.1`。

## Alternatives considered

**停在 alpha.5，只摘 rc.1。** 否决：rc.1 是在 alpha.5 之上的纯版本发布；合并保留完整上游 release 提交，避免 252 个 package 版本字段漂移。

**官方已记录 inherited-prefix append，因此丢掉 single-writer 持久化守护。** 否决：inherited-prefix 是否完整，与外进程 revision 漂移是不同的失败；官方仍没有跨进程写者拒绝。

## Consequences

fork 消费者在 `0.1.2-rc.1` 线上继续带着同一套本地补丁。`publish-fork --list --base 0.1.2-rc.1` 仍是 zw 发布集；npm `@crazx/*@0.1.2-rc.1.zw.1` 只在合入后的 tag 之后才存在。
