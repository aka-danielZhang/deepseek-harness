# Agent Note: Fork baseline bump to 0.1.2-alpha.5

Status: implemented

English | [中文](2026-09-03-bump-0.1.2-alpha.5.zh.md)

## Problem

Upstream published `dsh-v0.1.2-alpha.5`. The fork still sat on `0.1.2-alpha.3` plus zw-layer patches (WKWebView `Content-Length`, MCP status events, session concurrent-writer guard, `web:log`, todo-completion guard, model-effort memory, scoped republish module ids, hierarchical compaction fallback). Leaving the fork behind would mix official `0.1.2-alpha.5` packages with a stale `@crazx` zw line, and alpha.4 removed `Session.events`, so the fork-only todo-completion-guard would not typecheck against the new session log API.

## Decision

This bump merges tag `dsh-v0.1.2-alpha.5` and keeps every fork-only behavior:

- Persistence keeps upstream `SessionLogOffset`, `state.storage`, and the inherited-prefix materialize check, and still refuses appends when another process advanced the durable revision ([concurrent-writer note](../bug-fix/2026-08-18-session-append-concurrent-writer-guard.md)).
- `packages/bundle/base/cordis.patch.yml` keeps the `todo-completion-guard` row beside the upstream default that enables both `web_search` and `web_fetch` on the shared base.
- The todo-completion-guard reads the live log through `Session.snapshotEvents()` ([guard note](../feature/2026-08-19-todo-completion-guard.md)). The fork-only package version is aligned to `0.1.2-alpha.5` because upstream release bumps do not touch it.
- MCP `mcp-client/status`, remembered reasoning effort, `web:log`, WKWebView `Content-Length`, scoped republish module ids, and hierarchical compaction fallback stay.

Desktop and Oh My DSH consume this fork through `runtime/revision.json` and `@crazx/*` zw publishes. Retargeting those consumers is a separate change after a maintainer merges this bump and tags `v0.1.2-alpha.5+zw.1`.

## Alternatives considered

**Stay on alpha.3 and cherry-pick alpha.4/alpha.5.** Rejected: the session log read-intent rewrite, `SessionLogOffset` branding, inherited-prefix append rule, and web_fetch default are cross-cutting; carrying them as patches would cost more than a merge that keeps both sides' semantics.

**Drop the single-writer persistence guard now that official documents inherited-prefix appends.** Rejected: inherited-prefix completeness and foreign-process revision drift are different failures; official still has no cross-process writer refusal.

## Consequences

Fork consumers keep the same local patches on the `0.1.2-alpha.5` line. Anything that still called `Session.events` must use `snapshotEvents()`, `ownEvents()`, or `seq` instead. `publish-fork --list --base 0.1.2-alpha.5` remains the zw publish set; npm `@crazx/*@0.1.2-alpha.5.zw.1` exists only after the post-merge tag.
